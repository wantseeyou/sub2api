# 按分组授予只读查看权限

状态：2026-10-29 已完成实现和本地验收，尚未部署业务环境。

## 目标

多个公司共用 Sub2API 时，指定人员能够查看授权分组的上游账号情况、人员用量和使用记录，支持筛选、排序与分页，不能修改这些资源。

## 已确认

- 管理员直接向站内用户授权一个或多个现有分组，本次不建立公司及员工归属体系。
- 团队查看范围内只读；查看者保留普通用户的个人功能，包括管理自己的 API Key 和调用模型。
- 人员统计只展示所选时段内有授权分组用量的人，且只汇总其在授权分组的记录；删除 API Key 不影响既有历史用量。
- 允许展示共享上游账号的全局状态和剩余额度，明确标注共享口径；站内请求数、Token、费用仍限定为授权分组。
- 展示授权分组内对用户的计费金额；隐藏上游成本、内部备注、代理配置、其他分组信息和完整凭据。
- 首版新增“分组查看”入口，提供账号概况、人员用量、使用明细，支持适用的筛选、排序和分页，复用现有表格与图表样式。完整用户管理、错误请求详情和导出不在首版范围内。
- 授权后可以查看该组留存的授权前历史；Key 调组不迁移旧记录；撤权成功后的新请求立即失去相应访问资格。
- 跨组回退按日志现有分组归属展示；查看原组不自动授权回退组，需要时由管理员显式授权。
- 普通用户叠加分组查看授权；同组数据共同可见，不同公司通过不同分组隔离，上游账号仍可共享。

## 已核对的现状

- 网页后台的路由和菜单以 `isAdmin` 区分，不能仅靠隐藏操作按钮实现数据隔离。
- 现有受限 Admin API Key 已支持账号按分组可见；人员、使用记录与仪表盘的读取权限仍是全局范围，不能直接开放给分组查看者。
- 用户可使用哪些分组，不等于公司员工归属；用户可以通过不同 API Key 使用多个分组。
- 一个上游账号可以绑定多个分组，其上游额度属于整个账号；现有账号统计也不能直接作为分组内用量。
- 使用记录页面同时加载明细、汇总、图表、筛选候选和错误记录；相关入口必须采用一致的查看范围。
- 管理员使用记录响应的嵌套用户、API Key 资料超出查看所需字段；分组查看响应必须采用明确的字段白名单，不能原样复用。
- 历史日志有独立的 `group_id`，Key 调组不会改写历史；部分回退路径则以回退后的组写入日志，需要明确查看口径。

## 已确认方案

保留 `admin/user`，增加独立的分组查看授权，由管理员在用户管理中配置。新增专用查看入口和读取接口，复用现有查询、表格与图表中适用的部分；后台管理入口继续使用原权限边界。

完整数据规则、实现范围和验收标准见 [design.md](design.md)。

## 已确认的边界

- 分组是查看边界。同组内不同公司的记录都会对该组查看者可见；如果公司之间需要隔离，就必须使用不同分组。账号本身仍可跨组共享。
- 分组查看授权不改变用户调用模型的分组使用资格；调用落到哪个组，就按日志记录的归属参与该组统计。
- 原始入口组没有完整历史记录；跨组回退后，原组查看者可能看不到该次调用，回退组查看者则可能看到。
- 授权撤销约束后续请求，无法收回已经显示或保存的数据。
