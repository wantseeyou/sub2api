# 分组只读查看设计

状态：2026-10-29 已完成实现和本地验收；执行记录见 [tasks.md](tasks.md) 和 [verification.md](verification.md)。

## 权限模型

保留现有 `admin/user` 角色，为站内用户增加“可查看分组”授权，与 `allowed_groups` 等模型调用资格分开。一个用户可查看多个分组，多个用户也可查看同一分组；无授权代表没有团队查看资格。

增加 `user_group_view_grants` 关联表，以 `(user_id, group_id)` 为联合主键，关联用户和分组并记录 `created_at`。不引入公司、员工归属、自定义角色或通用权限配置体系。

管理员在用户管理中维护查看分组集合，原子的集合替换避免短暂的半授权状态；只能由现有管理员身份配置。查看者不能自行授权或修改他人的授权。个人功能仍按原有普通用户权限执行。

## 页面与字段

有查看授权的用户新增“分组查看”菜单；页面支持在授权分组内选单组、多组或全部，包含三个页签：

| 页面 | 展示 | 适用筛选 |
| --- | --- | --- |
| 账号概况 | 账号名称、平台、类型、状态、可调度状态、可见分组；共享上游额度、重置时间和快照更新时间；如展示站内用量则仅汇总所选分组 | 分组、平台、类型、状态、名称；站内用量可选时间 |
| 人员用量 | 用户名称及用于识别人员的邮箱、本组请求数、Token、对用户的计费金额、最近使用时间 | 分组、时间、人员、模型 |
| 使用明细 | 时间、用户、API Key 名称、日志所属分组、必要的账号标识、模型、请求类型、Token、计费金额、耗时 | 分组、时间、人员、API Key、账号、模型、请求类型 |

复用适用的表格、图表和筛选组件，提供排序、分页、重新读取数据及显示列选择。隐藏状态切换、编辑、删除、充值、额度重置、账号测试、令牌刷新、同步和批量操作。首版不提供完整用户管理、错误请求详情、导出及请求内容查看。

账号全局额度与组内站内用量分别标明口径。额度只读取已有快照；页面刷新不触发账号测试、主动探测或额度恢复，缺少快照时显示暂无数据。

## 数据范围

每个读取请求先验证登录状态，再从数据库读取最新查看授权。前端菜单和登录响应里的权限信息只用于展示；不能作为服务端授权依据。

- 未选择分组时查询全部已授权组；显式选择未授权组时拒绝请求。
- `user_id`、`account_id`、`api_key_id`、模型和时间条件只能进一步收窄范围。
- 范围为当前用户的显式授权集合，不自动包含公开组、回退组或账号关联的其他组。
- 没有任何有效授权时拒绝团队读取请求；无分组或无法确定分组的记录不向查看者展示。
- 账号列表按账号当前绑定分组与所选组的交集筛选、去重，返回的分组标签也仅包含授权范围。
- 使用明细和全部站内统计按 `usage_logs.group_id` 限制，不能用账号或 API Key 的当前分组代替。
- 人员从筛选范围内的使用记录聚合，不能按 `allowed_groups` 或用户当前持有的 Key 判断是否属于统计范围。
- 人员、Key、模型和账号筛选候选也由授权范围内的数据产生，不使用全站搜索候选。
- Key 调组或删除不迁移已保存的日志；人员已删除或账号已离开当前分组时，仅显示历史记录所需的安全标识，不授予当前资源详情权限。
- 共享账号的上游额度是明确允许的全局信息例外；该账号在其他组的请求、人员、Token 和费用不可见。

授予某组后可查询该组所有留存历史，仍须在页面选择时间范围并分页。部分回退请求的历史日志归回退组，遵循记录中的分组，不推断或补写原始入口组。

## 接口与字段隔离

新增 `/api/v1/group-view` 读取接口族，采用现有登录认证和独立的分组授权解析。集中解析本次请求的授权范围，并让账号查询、使用记录查询、汇总与候选查询显式接收该范围；不放宽 `/admin` 对普通用户的访问。

复用现有账号分组匹配、分页和统计计算中合适的逻辑。现有受限 Admin API Key 的账号授权可作为参考，但其 `users.read`、`usage.read`、`dashboard.read` 是全站权限，不能直接作为新的查看授权；其账号响应仍有内部备注等字段，也不能原样复用。

各页面采用明确的响应字段白名单。禁止返回完整账号凭据、完整用户 API Key、上游成本、计费内部倍率、代理配置、内部备注、其他分组信息、用户余额与通知配置；本次不返回 IP、User-Agent、请求正文和原始错误详情。嵌套用户和 Key 对象仅保留必要标识与显示名称，不能复用完整管理员 DTO。

只读权限按实际业务功能定义，不以 HTTP `GET` 或隐藏按钮代替。只登记所需读取接口，其他管理动作继续由原有管理员权限控制。

## 数据库与性能

- 新增授权关系，无需回填现有用户；空授权保持现有行为，不改角色值或既有计费数据。
- 每次请求执行一次带索引的授权读取，首版不缓存授权，以满足撤权成功后的新请求立即生效。
- 查询使用组集合过滤；通过 `EXISTS` 或适当聚合避免多组关联导致账号重复、人数或用量重复计算。
- 人员统计及账号站内用量采用批量聚合，不按人员、账号或分组逐条执行数据库、Redis 或 HTTP 请求。
- 现有 `usage_logs(group_id, created_at)` 索引可作为起点。实施时用目标查询及代表性数据检查执行计划、扫描量和聚合成本，再判断是否需要额外索引。
- 首版不接入缺少分组维度的全站统计缓存；若复用缓存，必须在重新校验授权后按实际组集合和全部筛选条件区分结果。
- 分页、时间校验和排序字段沿用适用的现有约束，不引入无限制的历史明细查询。

回滚可恢复旧版本并保留未被读取的新授权表，无需删除历史数据。该功能不改变模型调用资格、路由或计费行为。

## 验收标准

以下标准已通过本地验收，具体检查方式与覆盖边界见 [verification.md](verification.md)：

1. 甲授权 G1、G2，乙授权 G3；账号、明细、人员、汇总和筛选候选均不越过各自范围。篡改组或资源 ID、移除筛选参数也不能扩大范围。
2. 同一用户在 G1、G3 都有记录时，甲只能看到 G1 部分；同一账号跨 G1、G3 共享时，仅全局额度允许展示，站内统计仍隔离。
3. 同一账号同时属于 G1、G2 时，多组选中不重复列出账号或重复计数。
4. 人员列表只包含所选时段有记录的人；删除或调组 Key 后历史保持原归属；回退请求按记录中的分组展示。
5. 响应中没有完整凭据、内部配置或越权嵌套信息；管理接口直接调用仍拒绝；页面刷新不触发任何业务修改或主动探测。
6. 授权前历史可查看；撤权成功后的新请求立即拒绝相应组；清空授权后个人功能仍正常。
7. 列表、汇总、图表与候选的时间和分组口径一致；原管理员功能、普通用户功能、调用与计费行为保持兼容。
8. 执行相关格式、类型、现有测试和构建检查，并检查目标查询执行计划。必要验证优先用既有测试或临时用例，不默认新增长期保留测试。
