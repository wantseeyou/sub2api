# Codex 转发优化与独立检测

状态：2026-10-19 已按确认范围完成实现、统一审查及本地验证。执行清单见 [tasks.md](tasks.md)，实现、使用方式和验证记录见 [verification.md](verification.md)。

## 已确认范围

- 本次聚焦 Codex，提高现有 sub2api 转发的效率、稳定性和协议一致性。
- 检测目标是模型一致性，参考 ModelTrace 的输出统计方法，不开展实际编程能力评测。
- 不引入打票、票据保存、刷新或向业务请求注入探测所得状态。
- 8 项全部纳入：HTTP 出站压缩；线程/回合/窗口标识修复；回合路由状态来源追踪；HTTP/WS 字段一致性；首输出前保活与错误处理；轻量链路诊断；HTTP 入站转 WS 上游；独立模型一致性检测。

## 实现方案

### 转发优化

- HTTP 压缩限定在支持该能力的 ChatGPT Codex Responses 出站请求，只修改本次发送的请求副本；原始请求和重试输入保持可重读。避免在公共 API、compact、WS 帧或插件已处理的请求上重复压缩。
- 线程、回合、窗口信息优先保留客户端提供的有效语义；同一次尝试的头与请求体共享标识解析结果，不逐请求重造 turn_id 和回合开始时间，不将合法窗口固定为 `:0`。内部执行作用域必须包含调用方与原始线程，不能只按上游账号共享。
- 现有 `full` 模式明确配置了合并线程，直接改为线程隔离会改变既有语义。线程派生规则的变化须用默认关闭的账号级兼容开关启用，旧配置保持可读，启用需从新会话验证；不把旧 response 链或路由状态迁移到新身份。回合和窗口保真修复仍属于本期。
- turn-state 按实际状态值的摘要记录来源账号，结合可取得的调用方、线程和回合信息校验，不能仅记录“本会话最后一个账号”。只有真正回传给客户端时记录交付来源；未知来源不能假称已验证，更不能由网关主动补入。缓存有 TTL 和容量上限，不保存到诊断结果或日志中。
- WS 池中复用连接的握手头不能当作当前回合新返回的状态；现有按会话自动补入 turn-state 的路径也须受账号、回合边界约束。探测响应中的状态不得进入业务请求的复用状态。
- HTTP 与 WS 共用必要字段的规范化规则，保留各协议要求；不通过身份修复改写用户请求的模型、推理参数或对话内容。
- HTTP 普通转发和透传已有首输出前保活，本期修正提交响应头、错误与换号边界，并补齐 WS→SSE 等待路径，不另建重复心跳器。
- Codex 流式路径取得上游响应头或 WS 握手头后，首次心跳必须与可交付的本次上游响应头一起提交。已提交账号专属头后锁定该次尝试，不再透明换号；后续失败只写一次合法的 `response.failed` 终态，不能再切换 HTTP 状态码或拼接 JSON 错误。尚未提交前保留可证明安全的失败切换。
- 保活、模型输出和上游执行阶段分别跟踪；心跳与事件写入由单一写入者协调。普通 JSON 响应不注入 SSE 心跳；已有 compact 专用适配保持独立。
- 诊断记录实际传输、压缩是否启用、关联标识是否可用、失败阶段和回退原因；不保存凭据、Cookie 或业务对话正文。

### HTTP 入站转 WS 上游

- 增加默认关闭的独立开关；启用后仍须满足账号 WS 能力及现有路由限制。关闭时保留 HTTP 入站的原有传输选择。
- 客户端仍按原请求收到 SSE 或 JSON；账号强制 HTTP、compact 及插件传输限制继续优先。
- 传输选择必须覆盖当前提前返回的 passthrough 分支：保持其请求体语义，并实际走选中的传输；不能靠绕过 passthrough 把请求改成普通转换路径。插件命中时沿用插件支持的 HTTP 路径，记录原因，不悄悄绕过插件。
- 优先复用已有 WS 连接与明确的 `previous_response_id` 续接能力。HTTP 请求不因改走 WS 就自动获得原生 WS 会话循环中的历史状态；本期不缓存完整业务对话或擅自裁掉上下文来制造增量。
- 发送阶段至少区分“尚未发送”“已发送或部分发送，执行情况不明”“已收到响应”“已结束”。不能用下游是否输出代替这些状态。约束同时适用于 WS 内部重试、跨协议回退和外层换号，避免只禁用 HTTP 回退却继续在 WS 内部重放。
- 仅在确定尚未发送，或上游明确拒绝且允许安全纠正时，允许有界重试；丢弃 `previous_response_id` 还必须证明完整上下文可恢复，不能把只有增量或工具结果的请求当成独立新请求。跨协议回退还须能用 HTTP 等价表达。
- 请求写出后断连且执行状态不明时返回明确错误，不自动重放；部分写入也按可能已执行处理。保留客户端自行重试的既有协议，但不承诺整个系统恰好执行一次。
- 关闭开关可回退到原有 HTTP 入站路径；不执行参考仓库的审计表删除或数据清空迁移。
- WS 和压缩的收益按发送字节数、连接建立次数、首输出耗时与失败率验证；不把它们等同于输入 token 减少、缓存必然命中或防封号保证。

### 独立模型一致性检测

- 管理员从账号操作入口打开检测界面，选择一个或多个模型，手动运行、取消并查看最近结果。
- 覆盖普通 OpenAI OAuth/SetupToken 账号；复用目标账号的代理配置、模型映射、请求构造及插件/传输选择规则，不直接调用 `Forward` 或普通账号测试的完整业务流程。没有配置代理时遵循该账号既有直连配置；配置了代理但获取或使用失败时，不退回直连。
- 使用独立诊断上下文和新的线程/回合标识；WS 复用底层 dialer、构造器与解析器，但使用诊断独占连接，结束即关闭，不进入业务连接池、预热或粘性状态。探测仍受账号并发约束。
- 诊断失败、限流和分类结果只更新诊断结果，不调用业务停调、错误标记、用户余额扣费等逻辑。凭据获取也需检查副作用：可安全复用有效凭据；如果必须经过会停调账号的刷新路径，返回凭据不可用，由正常凭据管理流程处理，不借此重构整个 token provider。实际上游额度消耗应在界面说明并尽可能记录 usage。
- 复用参考实现中独立的挑战生成、指纹读取和分类能力；不接入票据获取、保存、刷新、复用及自动暂停账号逻辑。
- 只有协议正常结束且收到成功终态的完整样本才进入分类；`response.failed`、`response.incomplete`、取消、超时、解析失败和缺少终态的 EOF 均为检测失败。收到部分文本或数量达到门槛不等于样本有效。
- 固定内置指纹库、算法、挑战及请求参数 profile 的版本组合，不移植自动拉取更新器。没有对应指纹或无法建立可比较的采样条件时显示“无法判定”，不临时编造分类概率阈值。
- 每模型最多三次独立采样，每次使用新的诊断线程、回合和缓存键；先检查数量、重复和明显规律输出等挑战有效性，再比较多个有效样本。只有三个有效样本的候选模型一致时才提供“本次样本与参考指纹相符／疑似不一致”的经验线索；单次、冲突或无效样本均无法判定。三次一致不等于身份认证，不能宣称已校准准确率。
- 展示请求模型、实际映射模型、检测时间、结果及必要原因；记录实际传输、请求 profile、版本组合和样本数。候选模型及分数只作为诊断信息；未覆盖模型直接说明原因，避免无意义的付费探测。
- 最近结果复用 `accounts.extra`，以最近启动的一次为准。每个请求模型在启动时记录 `run_id`、开始时间、截止时间和配置摘要；终态写入必须仍匹配当前 `run_id` 和配置摘要，阻止旧任务覆盖新结果。映射、身份、代理或传输改变后，旧结果标明不再适用。
- 结果是服务端托管快照：普通编辑、创建、批量修改、导入不能伪造或覆盖，账号复制不得继承；仅管理员诊断接口写入，展示使用字段白名单，并纳入调度中立字段。
- 检测采用有界并发，同账号串行；沿用账号并发约束，多实例用共享互斥或租约限制，不依赖进程内 mutex。执行截止后不得继续写入；进程退出遗留的运行状态按截止时间显示过期。
- 上游请求直接受取消和超时控制，不复用业务请求为计费而脱离取消的上下文。取消后的状态保存允许短时独立 context，但仍须满足 `run_id` 条件。只存脱敏原因码和必要诊断摘要，不保存原始错误正文、响应头或探测全文。用户取消不等于上游一定未计费。

### 验证与交付

- 按转发修复、HTTP→WS、检测三个部分实施，最终统一审查；不整库移植参考项目。
- 复用现有后端、前端测试和构建；覆盖开关默认关闭、SSE/JSON、代理与插件约束、模型映射、未知模型、错误与取消、并发结果保存及账号编辑。
- 使用本地模拟上游验证压缩等价性、回合隔离、WS 事件转换和重放边界。没有真实凭据与授权时，不将本地检查描述为线上验证。
- 模拟边界至少包含：保活先于首个业务事件、之后上游失败；WS 请求发送后未回事件即断开；已返回 `response.created` 后断开；带工具结果的续链失效；代理或插件失败；检测输出截断与规律数字；取消后状态保存；旧任务迟到、配置变更、账号复制与并发编辑。
- 不新增长期保留测试；必要临时验证完成后清理。交付说明实际执行的检查及仍需上线后观察的指标。

## 已核实的实现边界

- 参考实现的分类结果没有最低概率门槛，不能直接把该概率当作能力评分或自动停调的充分依据。
- 参考探测使用打票代理池并允许无代理直连，且直接走 HTTP；需要单独设计与目标账号正常转发路径的对应关系。
- 参考仓库内置指纹库仅覆盖部分模型，不含 `gpt-6.1-sol`；界面能选到某个模型，不代表有该模型的有效指纹。运行时可加载更新库，但其覆盖范围需另行核实。
- 参考实现对 `gpt-6.1-sol` 的特殊规则是：预测为 `gpt-6-sol` 时标记 uncertain，其他分类标记 degraded；仅用内置库无法得到 normal，不能直接照搬。
- 目标账号的正常转发会执行模型映射，区分请求模型、计费模型与上游模型。合法映射和响应表现不一致应分别说明，不能混为同一结论。
- 模型挑战生成与输出分类可以从打票流程独立抽离；检测不依赖获取或复用探测中的路由状态。
- 现有 `accounts.extra` 可以保存最近检测结果，无须为此单独建表。但其通用更新仅合并顶层字段；实现需要防止不同模型的检测结果互相覆盖，以及账号编辑覆盖检测结果。
- 现有账号管理菜单和手动测试弹窗已有可复用的入口、模型选择与取消模式；检测结果可沿用展示型快照规则，避免触发调度桶重建。
- 当前 WS 重试结束后直接返回错误，并无实际 HTTP 自动回退。`wroteDownstream=false` 不表示上游尚未执行：流式事件可能被缓冲，非流式响应也可能尚未写给下游。

## 已确认范围的验收目标

| 范围 | 验收目标 |
| --- | --- |
| HTTP 出站压缩 | 适用的 Codex HTTP 请求经解压后与原始请求等价；公共 API、compact 与 WS 帧不误用此 HTTP 压缩逻辑。 |
| 线程、回合、窗口标识 | 保留合法回合、窗口语义；新身份规则启用后不同调用方和线程隔离，旧配置与旧续链不会被静默迁移。 |
| 回合路由状态来源 | 按实际状态区分来源，已知账号或回合不匹配时不复用；未知来源明确保留为未知，网关不主动注入无法验证的状态。 |
| HTTP/WS 字段一致性 | 相同请求的必要身份、路由和请求语义在两种传输中一致，保留各协议特有字段。 |
| 首输出前保活与错误处理 | 已取得上游响应头后的 SSE 等待可保活；本次有效头先于首个字节提交，提交后不再透明换号；失败只产生一次正确终态，普通 JSON 不混入 SSE。 |
| 轻量链路诊断 | 能定位实际传输、压缩、必要字段和回退原因；不记录凭据、Cookie 或业务对话正文。 |
| HTTP 入站转 WS 上游 | 默认关闭；启用后按请求要求返回 SSE 或 JSON，遵守账号强制 HTTP、插件和 compact 等约束，passthrough 请求语义不变；各层重试都不能仅以“下游无输出”为依据重放。 |
| 独立模型一致性检测 | 管理员可手动检测并查看最近有效运行记录；失败、无法判定与经验线索有区别，不改变调度、不污染业务连接或票据；取消、过时任务和账号复制均不产生错误快照。 |

验证优先复用现有测试；必要时使用临时验证，不新增长期保留测试，不进行未授权的真实上游探测。
